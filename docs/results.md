# 性能记录

以下数据来自原板卡运行和 SoC 仿真。仓库中的自检验证计算结果与接口时序，复测表中的耗时需要对应的整机环境和工作负载。

## 板卡上的量化模型推理

在 Minisys 板卡上执行量化 Llama 2 推理，以生成 token 的速率衡量端到端性能。

| GEMV 实现 | 推理速度（token/s） | 相对前一行 |
| --- | ---: | ---: |
| 原始 C | 1.324899 | — |
| 标量内联汇编 | 1.533335 | +15.73% |
| MAC4 内联汇编 | 1.730889 | +12.88% |

MAC4 每步处理四个字节，减少了内层循环的取数、乘加和循环控制指令。端到端推理还包含浮点缩放、归一化、激活和采样，计算内核的收益只作用于其中一部分。

## SoC 上的 GEMV 仿真

| Block Memory 配置 | 开始（μs） | 结束（μs） | 运行时长（μs） |
| --- | ---: | ---: | ---: |
| 标量内联汇编 | 0.55 | 222.93 | 222.38 |
| MAC4 内联汇编 | 0.55 | 83.92 | 83.37 |

以结束时间减去开始时间，标量耗时除以 MAC4 耗时约为 **2.67 倍**。两种程序都要执行地址计算、循环控制与访存，MAC4 本身也有多周期延迟，整段程序的加速比取决于这些开销。

## SoC 上的缓存仿真

| 缓存设置 | 同一测试程序总耗时（μs） | ICache 命中率 |
| --- | ---: | ---: |
| 关闭 ICache 与 DCache | 4965.740 | — |
| 开启 ICache 与 DCache | 1257.040 | 79.004% |

两次运行均记录了 1967 次取指和 26 次数据访问。开启缓存后约快 **3.95 倍**。这组仿真给主存访问加入了等待，频繁重复的取指命中后直接从 ICache 返回，减少了存储等待。
